# Собственный API «Обед рядом»

API создан по просьбе владельца сервера взамен недоступного API Политеха.
Он сохраняет формат объектов, пути и HTTP-методы из лабораторных 7–9.

## Адреса

- HTTPS: `https://82.23.173.175`
- Проверка службы: `GET /labs/api/health`
- Меню: `GET /labs/api/dishes`, `GET /labs/api/dishes/{id}`
- Заказы: `GET /labs/api/orders`, `GET /labs/api/orders/{id}`
- Создание: `POST /labs/api/orders`
- Изменение: `PUT /labs/api/orders/{id}`
- Удаление: `DELETE /labs/api/orders/{id}`

Меню содержит 30 блюд. В API категория салатов называется `salad`,
а frontend преобразует её в `starter`, как и в предыдущей реализации.

Для заказов обязателен параметр `api_key` в строке запроса — UUIDv4.
Frontend создаёт его случайным образом и сохраняет в cookie `obed_api_key`.
Сервер хранит хеш ключа и показывает пользователю только его заказы.
Страницы 8–10 на одном сайте используют один ключ; другой браузер или GitHub Pages
получат отдельную историю. Это учебная идентификация без формы входа.

POST принимает `full_name`, `email`, `phone`, `delivery_address`, `delivery_type`,
необязательные `subscribe`, `delivery_time`, `comment` и ID блюд:
`soup_id`, `main_course_id`, `salad_id`, `drink_id`, `dessert_id`.
Проверяются обязательные поля, категории блюд, пять комбо, время доставки
07:00–23:00 с шагом 5 минут и ограничение 10 заказов на пользователя.
Время сравнивается с текущим временем в Москве.

PUT меняет только `full_name`, `email`, `phone`, `delivery_address`,
`delivery_type`, `delivery_time`, `comment`. Состав заказа не меняется.
При переходе на доставку `now` значение `delivery_time` сбрасывается в `null`.
Ошибки возвращаются JSON-объектом `{"error": "..."}` и HTTP-статусом 4xx/5xx.

## Развёртывание

Исходники API находятся в `/opt/obed-api`, база SQLite —
`/var/lib/obed-api/orders.sqlite3`. База находится вне папки сайта и сохраняется
при перезапуске службы и переключении версий сайта. Файл базы не включается в Git.

Служба `obed-api` запускает Gunicorn от `www-data` на `127.0.0.1:8772`.
Nginx принимает публичные запросы по `/labs/api/` и передаёт их этой службе.
Публичный доступ к `/server/` закрыт. В лог API не записывается строка запроса с ключом.

Первичная установка: загрузить каталог `server` и выполнить от root `sh install.sh`.
Скрипт предназначен для существующего сервера `82.23.173.175` с Nginx и
каталогом сайта `/var/www/fundamentals/current`.

Сертификат Let's Encrypt выпускается для IP-адреса. Он короткоживущий;
таймер `obed-certbot-renew.timer` проверяет продление два раза в день.
После продления Nginx перечитывает сертификат. HTTP перенаправляется на HTTPS.

При обновлении API скопировать `app.py`, `menu.json`, `requirements.txt`
в `/opt/obed-api`, установить зависимости в `/opt/obed-api/venv`
и выполнить `systemctl restart obed-api`. Существующую базу не удалять.

## Локальная проверка

Создать virtualenv и установить `requirements.txt`. На Windows Gunicorn пропускается.

```text
python -m unittest discover -s server -p "test_*.py" -v
node --test 9/tests/api.test.cjs
```

Серверные тесты проверяют CRUD, изоляцию пользователей, все 32 комбинации категорий,
поля и время доставки, CORS, лимит заказов при параллельных запросах и сохранение
данных при повторном создании приложения. Тесты используют отдельные временные базы.
