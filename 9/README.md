## Что сделано

- Создана страница `orders.html` с историей заказов.
- Заказы загружаются с API и сортируются от новых к старым.
- Для каждого заказа показаны дата, состав, стоимость и время доставки.
- Кнопка «Подробнее» открывает полную информацию в модальном окне.
- В модальном окне редактирования можно изменить данные доставки и получателя.
- Изменения отправляются на API методом `PUT`.
- Перед удалением открывается окно подтверждения, затем выполняется `DELETE`.
- После изменения или удаления список заказов загружается заново.
- Ошибки и успешные операции показываются пользователю в уведомлениях.

Для проверки формы используйте вымышленные данные.

## Доступность API и проверка без него

По просьбе владельца проекта основной режим использует собственный API:
`https://82.23.173.175/labs/api`. Заказы сохраняются в SQLite на сервере.
UUIDv4 создаётся в браузере и сохраняется в cookie. Он передаётся в параметре
`api_key`; сервер возвращает только заказы, принадлежащие этому ключу.
Ключ из СДО не требуется. Исходники API находятся в `server/`.
Если API недоступен, страница сообщает причину и предлагает
повторить загрузку либо открыть отдельный учебный режим.

Учебное меню:
https://82.23.173.175/9/lunch.html?demo=1

Учебная история:
https://82.23.173.175/9/orders.html?demo=1

В этом режиме 30 блюд загружаются через `fetch` из `demo-dishes.json`.
Можно собрать комбо, оформить заказ, открыть историю, изменить данные и удалить
учебный заказ. Изначально история пуста. Заказы сохраняются только в этом браузере
в отдельном ключе `lab9DemoOrders`, а выбранные ID — в `lab9DemoSelectedDishIds`.
Настоящие заказы не затрагиваются. На каждой странице режима есть предупреждение.

Учебный режим предназначен для отдельной тренировки интерфейса. Основной режим
выполняет настоящие GET, POST, PUT и DELETE к собственному серверу.
API Политеха, указанный в оригинальном задании, заменён по просьбе владельца проекта.
